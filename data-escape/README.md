# هروب البيانات

لعبة جري تعليمية بثلاثة مسارات لمنصة «سايبر أوير». يحمل اللاعب حزمة بيانات ويجري بها في مدينة رقمية إلى الخزنة الآمنة.
في الطريق تسع بوابات قرار، وفي كل بوابة رسالة أو إشعار أو محادثة يقرر اللاعب كيف يتصرف معها.

- تعمل كاملة في المتصفح على جهاز اللاعب (جوال أو كمبيوتر)، بلا خادم ألعاب وبلا تسجيل.
- عربية من اليمين إلى اليسار، بالشخصيات الثلاث نفسها: الولد، البنت، وسايبر.
- نظام الدرجات هو نظام سلسلة «سايبر أوير» نفسه، والمنصة تعيد حساب الدرجة من سجل القرارات.

## التشغيل

```bash
npm install
npm run dev        # للتجربة أثناء التطوير: http://localhost:5173
npm test           # 21 اختبارًا: الدرجات، عدالة المسار، منطق القرارات
npm run build      # فحص المحتوى + فحص الأنواع + إنتاج المجلد dist/
npm run preview    # تشغيل النسخة المبنية
```

المجلد `dist/` هو اللعبة الجاهزة (حوالي 8 ميغابايت)، ويعمل من أي مسار فرعي.

## طريقة اللعب

| الحركة | الكمبيوتر | الجوال |
|---|---|---|
| تغيير المسار | السهمان الأيمن والأيسر | سحب يمينًا أو يسارًا |
| القفز | السهم الأعلى أو المسافة | سحب إلى الأعلى |
| الانزلاق | السهم الأسفل | سحب إلى الأسفل |
| إيقاف مؤقت | Escape | زر الإيقاف أعلى الشاشة |

- يمكن إظهار أزرار لمس من الإعدادات بدل السحب.
- أول أربعة عوائق في المرحلة الأولى دروس: يتباطأ الوقت ويظهر الشرح لحظة الحاجة إلى الحركة، ولا تُخصم طاقة.
- زر «التدريب» في القائمة مسار قصير بلا عقوبة ولا درجات، فيه الحركات وموقف واحد.

### المراحل

| المرحلة | الموضوع | القرارات |
|---|---|---|
| ١. شارع الرسائل | التصيّد والروابط والطلبات المفاجئة | رسالة تطلب الدفع، أي سطر يكشف الاحتيال؟، نافذة تحديث مفاجئة |
| ٢. منطقة الحسابات | كلمات المرور ورموز التحقق | كلمة مرور جديدة، من يطلب رمز التحقق؟، محاولة دخول إلى حسابك |
| ٣. الطريق إلى الخزنة | تطبيق ما سبق في مواقف جديدة | أي الرسالتين تصدّق؟، رتّب ما تفعله، رسالة تستعجلك عند الخزنة |

لكل قرار موقفان مختلفان (18 موقفًا)، واللعبة تفضّل الموقف الذي لم يره اللاعب من قبل، فتختلف الجولة عند الإعادة.
أنواع التفاعل أربعة: اختيار التصرف، تحديد الدليل داخل الرسالة، المقارنة بين رسالتين، وترتيب الخطوات.

### الطاقة والحماية

- **طاقة الحركة (٣):** تنقص بالاصطدام. إذا انتهت يعود اللاعب إلى بداية المقطع ومعه درع. لا تؤثر على الدرجة.
- **حماية الحزمة (٣):** تنقص بالقرار غير الآمن وتعود بالقرار الآمن من أول مرة. إذا انتهت يعيد اللاعب المقطع ثم يحاول الموقف من جديد.
- **الأدوات:** درع (يمتص اصطدامًا)، عدسة (تكشف تفصيلًا في الرسالة)، تلميح. تُجمع من الطريق.

## الدرجات

نتيجتان مستقلتان تظهران في النهاية:

- **تقييم القرارات الأمنية (من 100):** هو الدرجة الوحيدة التي تُحفظ للطالب.
  - القرار الآمن من أول مرة يأخذ وزنه كاملًا. القرار الخاطئ ثم التصحيح يأخذ 60% من الوزن.
  - النجاح من 70% مع حل كل القرارات. الوقت والسرعة لا يدخلان في الدرجة.
  - القواعد في `src/game/assessment.ts` (لم يتغير عن القالب) والأوزان في `src/data/missions.json`.
- **نقاط الجري والنجوم:** للمتعة فقط (المسافة، أجزاء البيانات، العوائق، مكافأة الموقف الجديد). لا تُحفظ كدرجة.

## الربط بالمنصة (React)

مثل ألعاب السلسلة تمامًا:

1. انسخ `dist/` إلى `public/games/data-escape/` في المنصة.
2. استخدم المكوّن المشترك `integration/react/CyberAwareGame.tsx` (إن لم يكن منسوخًا من لعبة سابقة).
3. الرسائل: `game.started`، `game.decision`، ثم `game.completed` وفيها `{ result, ledger, fun }`.
   كل رسالة بالشكل `{ type, protocolVersion: 1, gameId: 'data-escape', data }` وتُرسل إلى الأصل المحدد في `?parentOrigin=` فقط.
4. لحفظ الدرجة: أرسل `gameId` و`runId` و`ledger` إلى الخادم وأعد الحساب هناك بملف `missions.json` الخاص بهذه اللعبة.
   الحقل `fun` (`stars`، `runScore`، `bits`، `hits`، `falls`، `seconds`) للعرض فقط ولا يُحفظ كدرجة.

التدريب والمراجعة بعد النتيجة لا يرسلان شيئًا للمنصة ولا يغيران النتيجة.

## ما اختلف عن الوصف الأصلي ولماذا

| في الوصف | في اللعبة | السبب |
|---|---|---|
| ٤ مواقف في الجولة | ٩ قرارات في ثلاث مراحل متصلة (٣ لكل مرحلة) | نظام الدرجات يحتاج قرارات ثابتة مجموع أوزانها 100، والمدة الكلية ٧ إلى ١١ دقيقة |
| بعد الخطأ ينتقل إلى موقف معالجة مختلف | يعود الموقف نفسه كـ«فرصة المعالجة»، وبعد التصحيح تظهر نصيحة «ماذا تفعل في الواقع» | سجل القرارات الذي تعيد المنصة حسابه يقبل تصحيح القرار نفسه فقط |
| الخيارات مرتبطة بالمسارات | لكل خيار رمز ولون بوابة، واختياره يحرّك اللاعب إلى مساره، ثم زر تأكيد صريح | على شاشة الجوال الرأسية لا تتسع ثلاثة أعمدة لنص عربي مقروء |
| مواقف سليمة وأخرى مشبوهة | قرار «أي الرسالتين تصدّق؟» يضع رسالة سليمة بجانب مشبوهة | يبقى لكل قرار إجابة آمنة واحدة كما يتطلب نظام الدرجات |
| مؤقت في القراءة | لا مؤقت إطلاقًا، إلا عدًّا وهميًّا في آخر قرار يكشف أنه «مجرد ضغط» | لا أفضلية للإجابة الأسرع، والعدّ نفسه جزء من الدرس |
| حفظ التقدم | تُحفظ الإعدادات والاسم وأفضل نتيجة والشارات والمواقف التي رآها اللاعب | الجولة المقيَّمة جلسة واحدة برقم واحد؛ إعادة تحميل الصفحة تبدأ جولة جديدة |
| موسيقى ومؤثرات | تُولَّد داخل المتصفح بلا ملفات صوت | حجم أصغر وبلا تكلفة، والموسيقى تتصاعد مع السرعة وتهدأ عند القراءة |

## بنية المشروع

| المسار | ما فيه |
|---|---|
| `src/data/missions.json` | القرارات وأوزانها ومعرّفات التصرفات (ما يعيد الخادم حسابه) |
| `src/data/content-ar.json` | المواقف الـ18 وكل نصوص القصة |
| `src/data/ui-ar.json` | نصوص الواجهة |
| `src/data/balance.json` | أرقام اللعب: السرعات، أطوال المقاطع، القفز، النقاط |
| `src/run/track.ts` | توليد المسار مع ضمان طريق آمن دائمًا |
| `src/run/sim.ts` | حركة اللاعب والاصطدام والجمع (بلا رسم، قابل للاختبار) |
| `src/run/decision.ts` | اختيار الموقف وترتيب الإجابات وربطها بمعرّفات التصرفات |
| `src/run/city.ts`، `actors.ts` | المدينة والشخصيات ثلاثية الأبعاد |
| `src/run/game.ts` | تسلسل اللعبة كله |
| `src/run/input.ts`، `sound.ts`، `storage.ts` | التحكم، الصوت، الحفظ المحلي |
| `src/ui/` | الواجهة والتصميم |
| `src/game/` | من قالب السلسلة: الدرجات والشخصيات (بلا تغيير) |
| `tests/`، `scripts/validate.mjs` | الاختبارات وفحص المحتوى |

لتغيير موقف أو إضافة موقف جديد يكفي تعديل `content-ar.json` ثم `npm run validate`.
لمراجعة صياغة كل المواقف دون لعبها: `npm run questions` يكتب الملف `QUESTIONS_AR.md`. كل موقف يبدأ بسطر «الموقف» (`sceneAr`) الذي يشرح السياق قبل الرسالة.
لتغيير الأوزان أو القرارات: عدّل `missions.json` ثم `npm run fixtures` وارفع `assessmentVersion`.

### أدوات المطور (في `npm run dev` فقط)

- `?demo=good` أو `mixed` أو `poor`: اللعبة تلعب نفسها (كل الإجابات آمنة، بعضها خاطئ، كلها خاطئة أول مرة).
- `window.__game.simulate(ثوانٍ)`: تقديم اللعبة بخطوات ثابتة، مفيد حين يكون التبويب مخفيًا.
